# Доверенная цепочка GigaChat

Поместите сюда проверенную PEM-цепочку НУЦ Минцифры (корневой и выпускающий
сертификаты), например `gigachat-chain.pem`, и пересоберите образ через Makefile.
Каталог включается в образ как `/app/certs`; задайте
`GIGACHAT_CA_BUNDLE=/app/certs/gigachat-chain.pem` в `.env`.

Сертификаты получают по официальной инструкции:
https://developers.sber.ru/docs/ru/gigachat/certificates

Автоматическая загрузка — `make gigachat-ca`: получает root/sub с gu-st.ru по проверяемому
HTTPS, проверяет имя и срок CA, сохраняет цепочку и файл происхождения с SHA-256 DER.
При сетевой ошибке существующая цепочка не перезаписывается. Если gu-st.ru недоступен,
получите официальные PEM через https://www.gosuslugi.ru/crt и передайте пути для установки.

Для скачанных файлов есть `make gigachat-ca-install`: принимает PEM и DER (`.cer`).
Папка-источник по умолчанию — `~/Downloads`, переопределяется через `CERT_DIR`.
Пример для комплекта Госуслуг:

```sh
make gigachat-ca-install ARGS='--certificate /incoming/Russian_Trusted_Root_CA.cer --certificate /incoming/Russian_Trusted_Sub_CA.cer --certificate /incoming/Russian_Trusted_Sub_CA_2024.cer'
```

Все сертификаты проверяются до замены рабочего bundle: CA-признак, допустимое имя,
начало и конец срока действия. Сохраняются SHA-256 DER и имена исходных файлов.
Затем пересоберите/перезапустите сервисы и выполните `make check-gigachat`.
Реальная проверка цепочки и имени сервера происходит при TLS-подключении.

Проверка TLS остаётся включённой. Без нужной цепочки соединение завершится ошибкой,
а не перейдёт в незащищённый режим. Пользовательские файлы этого каталога не коммитятся.
Не помещайте сюда закрытые ключи и токены: содержимое копируется в образ.
