# Эксперименты — протокол stage6-v1

04.11.2026. Зафиксирован до запуска матрицы этапа 6. Требования: Ф8 и §4.3 ТЗ,
дополнение №1, `LINKING_ACCEPTANCE.md`. Историческая приёмка 4.6 неизменна.

## Выборка и метод

Основная версия `196ecb8f-fe6e-41c6-8785-a4faf69a6b1f`, fingerprint
`fe98fa1d6fdf24237c357b8761ec0e1bf35e8f44fbe9bb8eeb5491c1f9390103`.
Seed и сохранённые split берутся из версии, заново не генерируются. N — все
in_scope входящие по оценочной разметке, включая ошибки и no_target. Рабочий
вид не исключает документ из N. Кандидаты — все договоры той же версии и клиента
не позже документа; split кандидата не ограничивается. Разметка присоединяется
только оценщиком; движок не получает gold, split, case, expected или пути.

В основных вариантах клиент/вид/дата — общая карточка Qwen. Сравнение моделей
условно на этой карточке, **не независимое end-to-end**. Сохранённые реальные
извлечения и BGE-M3 переиспользуются; ошибки YandexGPT не повторяются и не
заменяются ответами другой модели. Новых вызовов LLM исполнитель не выполняет.

## Матрица и выбор модели

Пять основных вычислений: rules, semantic, combined × Qwen/YandexGPT/GigaChat.
Девять сочетаний ТЗ отображаются на эти пять: rules и semantic одинаковы для
всех трёх моделей. В экспорте у общих baselines перечисляются все три модели;
дубли не считаются независимыми прогонами.

До test выбирается лучшая допустимая combined-модель по **tune**: максимальный
охват при Precision ≥0,98 и M>0, затем Precision, затем порядок
**Qwen → YandexGPT 5.1 Pro → GigaChat 2 Lite** (фактическая модель GigaChat-2).
Если допустимой combined-модели нет, три абляции имеют статус BLOCKED с причиной;
модель не выбирается по test. Всего в полной серии восемь конфигураций.

Абляции выбранной модели, каждая с собственным tune:

- no_llm: отдельные regex-поля **и карточки всех документов**, без скрытого Qwen;
  исходные карточки не меняются. BGE-M3 остаётся реальным и неизменным.
- no_checks: специальные проверки и штрафы combined отключены; общие ограничения
  клиента, даты, версии и цели обязательны.
- no_sem: смысловой вклад нулевой, веса не перераспределяются.

Пороги выбирает неизменная `stage4-tune-v1`: конечные точки 0, 1 и оценки tune;
максимальный охват при Precision≥0,98/M>0, затем Precision, затем больший τ_a.
τ_r≤τ_a: максимум достижимых gold-связей через рекомендации/top-3 разбора,
затем меньше разборов, затем больший τ_r. Веса 0,45/0,15/0,15/0,05/0,20,
штрафы 0,20/0,05. Нет допустимого порога — NO_FEASIBLE_CONFIGURATION, test
не выполняется. Настройка по test запрещена.

## Freeze и повтор

Перед test сохраняются конфигурация, снимки моделей/промптов/эмбеддера, коммит,
хеш фактического кода, входов/полного пула кандидатов и отдельный оценочный хеш.
Вся серия проходит tune/выбор модели до первого test. Начало test фиксируется
отдельной транзакцией. История ранее просмотренного test сохраняется, для
основного корпуса reused_test=true. Изменение входов после freeze останавливает
прогон, не становится ошибкой модели и требует новой серии.

Исходы, извлечения, физические вызовы, векторы и замеры связаны с прогонами
many-to-many. Повтор не переприсваивает историю. Расход выполнения (новые LLM:
0 ₽), стоимость использованных исходных вычислений и доля переиспользования
показываются раздельно. Неизвестная стоимость — null, не ноль. Локальный расход
CPU в рубли без заданного тарифа не переводится.

## Метрики и нормализация

Tune и test раздельно. Срезы: all, real, synth, synth_extra, hard, hard:1…9,
kind:допсоглашение/счёт/акт/УПД. Трудные срезы пересекаются, их нельзя суммировать.
N/M/верные/gold, Precision/Recall/F1, охват, документная точность, разбор, ошибки,
Recall@3 — по §4.3 ТЗ. M=0: Precision=0, доля ошибок=null («—»).
Для каждого отношения сохраняются числитель и знаменатель; пустой срез явный.

Извлечение оценивается по всем in_scope документам данного split, включая договоры.
Вид — точное совпадение; номер — Unicode NFKC, casefold, удаление пробелов и №,
унификация тире (без исправления OCR); дата — календарная ISO; ИНН — цифры;
сумма — Decimal, точное равенство без допуска. Невалидный ответ — пропуск.
Отсутствующий столбец в annotated_fields — не размечено. Пустой real-реквизит
номера/даты/ИНН/суммы консервативно считается не размеченным, а не отсутствующим;
пустое поле синтетики — эталонно отсутствует. Число исключённых показывается.

Невалидность — по всем выбранным извлечениям; ненайденные цитаты — только среди
предоставленных непустых цитат, отсутствующие основания отдельно. Ресурсы:
уникальные физические вызовы (включая транспортные/корректирующие попытки той же
задачи), токены/время/стоимость на документ и отдельно выполнение связывания из
кэша. Суммирование общего расхода серии дедуплицирует физические ID.
Qwen: «открытые веса, облачное размещение». Локальное время лишь **расчётное**:
input_tokens/v_prefill + output_tokens/v_decode, только при заданных скоростях.

## Реализация и использование

`/experiments` создаёт серию в очереди, показывает ход выполнения и причины остановки;
режим «выбор модели + три абляции» выполняет три основных combined-tune и абляции.
Режим single предназначен для отдельного метода/модели. REST возвращает ID **серии**
(UUID), её прогоны и прогресс; POST идемпотентен по UUID запроса. Один и тот же ключ
с другим телом отвергается. Экспорт до завершения — 409, авторизация — cookie.
Порогами из запроса заменить процедуру tune нельзя.

Снимки и dataset хранятся в БД, ETag скачивания равен dataset_hash. CSV — длинный
формат с таблицей/метрикой/split/срезом/числителем/знаменателем. JSON CLI содержит
манифест и все рейтинги контрольных случаев. Работающие контейнеры получают коммит
при сборке через Makefile; фактический код дополнительно хешируется независимо.
Команды запуска, повтора, экспорта и проверки описаны в `make help`.

Из исхода прогона можно создать рабочую копию. Совпадающие исходные входы и
завершённая сессия с initial_inputs=true позволяют отобрать замер для этого прогона.
Правки/повторная обработка исключают исходный замер. Копии regex-абляции обрабатываются
обычным рабочим конвейером и всегда имеют initial_inputs=false: их длительности
не выдаются за исходное измерение regex. Замеры в dataset — снимок на момент завершения;
будущие измерения доступны через `review_measurements`, без переписывания dataset.
