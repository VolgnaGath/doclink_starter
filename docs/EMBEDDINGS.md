# Локальные эмбеддинги — BGE-M3 v1

02.11.2026. Пункт 4.3 и embedding-часть 4.4 плана этапа 4.

## Модель и воспроизводимость

- `BAAI/bge-m3`, ревизия **5617a9f61b028005a4858fdac845db406aefb181**.
  Ревизия проверена через API Hugging Face до запуска; `main` при кодировании
  не используется. `trust_remote_code=false`.
- `sentence-transformers`, PyTorch CPU float32, SDPA, CLS pooling исходной модели,
  1024 компоненты, нормализация L2. Нет дополнительного query-prefix/LLM-предмета.
- Lock: sentence-transformers 5.7.0, transformers 4.57.6, torch 2.15.0+cpu,
  numpy 2.5.4, pgvector 0.5.1. Для Linux обеих архитектур используется официальный
  CPU-индекс PyTorch, CUDA-зависимости в Linux-окружение не устанавливаются.
- Модель загружается лениво внутри worker и удерживается между заданиями одного
  процесса. API не загружает веса. По умолчанию 2 CPU-потока, batch=1.
- Веса и HF-кэш — volume `models` в `/data/models`. Установку выполняет отдельная
  команда из Makefile. Обычная обработка `local_files_only=true`; ошибка загрузки
  сохраняется как ошибка обработки, другой embedder не подставляется.

## Смысловой вход и длина

Вход `app/services/embeddings.py` — только текст, без ORM-объектов, LLM-ответов,
имён файлов и разметки. Подготовка одинакова для всех сравниваемых моделей.

`semantic-text-v1`: NFKC; удаление управляющих/форматирующих символов Unicode
(категория C), кроме пробельных; все пробельные последовательности заменяются
одним пробелом; края обрезаются. Номера, даты, имена, суммы и договорные условия
не удаляются. Пустой результат — ошибка. NFKC, в частности, переводит `№` в `No`.

Токенизируется **весь** подготовленный текст, `truncation=false`, без специальных
токенов. Затем последовательные неперекрывающиеся окна по 510 содержательных
токенов; ещё 2 специальных токена XLM-R. Идентификаторы токенов передаются прямо
в ST.forward — без decode/re-tokenize и без неявного отсечения ST.encode.
Вектор каждого окна нормализуется; затем среднее, взвешенное числом содержательных
токенов окна, и итоговая L2-нормализация (`dense-cls-token-weighted-v1`).

Лимит модели 8192; в v1 окно **512**, чтобы ограничить CPU/RAM на текущем стенде.
Ограничения: 1 000 000 исходных символов и 256 окон (до 130 560 содержательных
токенов при текущем окне). Превышение — явная ошибка, **не успешная обрезка**.
Для успехов `truncated=false`, сохраняются tokens/chunks и число символов.
Действующее правило обрезки LLM 6000+2500 этим не меняется.

## Кэш и хранение

Миграция `0004` содержит embedding-часть хранения; документные исходы и пары
кандидатов добавляются следующей миграцией в оставшейся части 4.4.

- `embeddings`: один успешный физический вектор на `input_hash`, SHA подготовленного
  текста, полный снимок параметров, ревизия, tokens/chunks, длительность и время.
  pgvector `vector(1024)`, CHECK единичной нормы, HNSW cosine-index. Ошибок в кэше нет.
- Ключ — SHA-256 канонического JSON снимка + фактического подготовленного текста.
  Снимок включает модель, ревизию, версии подготовки/кодирования, окно и лимиты,
  нормализацию, dtype/attention/batch, CPU-потоки, версии четырёх вычислительных
  пакетов и архитектуру. Идентификаторы документа/версии/клиента в ключ не входят.
  Одинаковый фактический локальный вход может переиспользоваться между версиями.
- `document_embeddings`: ссылка документа на вектор, SHA **исходного** текста,
  исходные/подготовленные символы, cache_hit. Прежние записи не перезаписываются;
  другой текст или конфигурация дают новую связь происхождения.
- Вектор и происхождение фиксируются одной транзакцией. Сессионная advisory lock
  по фактическому ключу предотвращает параллельное вычисление одного входа.
- Каждый запуск, в том числе cache hit и ошибка, записывает `stage_timings`/embed.
  Сырой текст, вектор, `gold` и `anon_maps` не пишутся в текстовые логи/отчёт smoke.
- Сходство — точный cosine допустимого пула. Наличие HNSW-индекса не разрешает
  отсекать кандидатов до проверок ядра. Сервис ранжирования подключается далее.

## Очередь

Явная постановка `embed` через CLI, захват существующим worker с SKIP LOCKED;
блокировка документа сериализует постановку. Payload содержит хеш исходного текста,
ключ вектора и конфигурацию. Изменение входа до исполнения — терминальная ошибка;
новая постановка не выдаёт старую конфигурацию за актуальную.

Повтор текущего задания возвращает существующее; терминальную ошибку повторяет
только явный retry. Потерянное CPU-задание возвращается в очередь, когда освобождена
advisory lock worker. Если вектор уже зафиксирован, восстановление читает кэш.
CLI drain выбирает только embed, не запускает стоящие рядом extract-задания.
Автоматическая цепочка extract→embed→link подключается в оставшейся части 4.4.

Актуальные команды — `make help`. Для изолированной живой проверки volume весов
задаётся `EMBEDDING_MODEL_VOLUME`, по умолчанию `doclink_starter_models`.
Проверочный контейнер монтирует его только для чтения; его БД/файлы отдельные.
