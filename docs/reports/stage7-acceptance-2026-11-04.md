# Этап 7 — интеграция mock1c, 04.11.2026

## Итог

Этап реализован и проверен: автоматический импорт inbox, общий конвейер,
подтверждение и отмена, надёжная обратная доставка, наблюдаемость и повтор.
Основная БД — 0011. Описание обмена — `docs/INTEGRATION.md`.

## Реально выполнено

Изолированный Docker-стенд `doclink-integration`, PostgreSQL 16 + pgvector,
живые HTTP API/mock1c/worker, Chromium **156.0.8078.4**.

1. Подготовлены договор и счёт с одинаковым временем регистрации, внешними
   UUID одного клиента. Worker сам забрал каталог/файлы и создал 2 документа.
2. Настоящий regex извлёк реквизиты; настоящий BGE-M3 CPU вычислил 2 вектора,
   обе привязки `cache_hit=false`. Скриптовых векторов/ответов моделей нет.
3. Получена recommendation. До решения бухгалтера links и журнал mock1c пусты.
4. Через браузер подтверждена связь «основание»; mock1c принял create.
5. mock1c остановлен. Через браузер отменена связь; локальное решение сохранилось,
   ошибка ConnectError записана отдельно, доставка осталась ожидающей.
6. После восстановления mock1c remove доставлен с прежним event_id, всего 3
   попытки отмены (2 ConnectError, затем 200). SQLite-журнал содержит ровно
   create/remove и 0 активных связей.
7. Worker/mock1c перезапущены, повторно запрошен опрос. Сохранены прежние
   2 document ID, 1 result ID и ровно 2 события журнала; JS-ошибок 0.
8. Независимый аудит БД подтвердил 2 извлечения, 2 реальных вектора, 1 исход,
   1 отменённую связь, 2 доставленных события, 0 активных jobs, 0 llm_calls.

Документ счёта: `7597df50-ec84-4ccf-9f7e-8ed7f8d7a08c`.
Результат: `6785cdc4-68a5-462d-b6fe-8bd8b86bc302`.

Это **техническая приёмка интеграции с реальным regex**, не повтор облачной
LLM-приёмки и не оценка качества модели. Облачный конвейер ранее принят на
этапе 5. Для нового платного прогона нужен явный допуск; он здесь не включался.
Технические пороги 0,2/0,1 живут только в отдельной БД, рабочий метод не менялся.
Измеренное время embed 117266/48978 мс относится к этой нагруженной среде и
не является оценкой локального времени Qwen или сравнительным экспериментом.

При подготовке браузерного harness устранены гонки ожидания запуска API и
восстановления mock1c; финальный сценарий целиком прошёл. Регрессия также
обнаружила необходимость фильтровать уже queued delivery при отключении
коннектора — исправлено и покрыто отдельным сценарием.

Ограничения: это модель OData на заглушке, не проверка на живой 1С. Для обратной
доставки обеим сторонам нужны внешние ID; отсутствие привязки явно blocked.
Поздно опубликованные записи с прошлой регистрационной датой забираются полным
опросом. Обычный протокол требует публикации с актуальным временем регистрации.
