# Оперативный конвейер (5.3)

03.11.2026. Миграция `0008`, PostgreSQL/jobs, один рабочий пользователь.

## Регистрация и конфигурация

`register_batch` — общий сервис для веба и REST. Проверяет рабочего клиента
и наличие конфигурации до записи файлов. Клиенты корпуса недоступны для загрузки.
Принимает PDF/DOCX/TXT, `is_anonymized` по умолчанию false; возвращает имя, ID
принятого документа либо причину отказа для каждого файла. Лимит размера — на файл.
Корректные файлы запроса получают общий batch_id. Ошибка формата/размера не мешает
другим файлам. Повреждение поддерживаемого формата обнаруживается на text:
оригинал сохраняется, документ получает ошибку обработки. Одинаковый blob не
означает одинаковый документ. Повторно загружать следует только файлы с отказом;
для принятого документа используется повтор неудачного этапа.

`operational_config` — единственная явно установленная конфигурация.
`make configure-pipeline` устанавливает combined + Qwen из замороженной приёмки 4.6:
модель, совпадающий снимок извлечения (промпт/схема/параметры/тарифы), пороги и BGE-M3.
Порог рекомендации — 0,1961963968090486, разбора — 0,1840638746253075.
Снимок копируется в `processing_pipelines` и происхождение исхода поиска;
изменение настройки не переписывает принятые документы. `origin_protocol_hash`
указывает источник настроек, рабочая загрузка не становится исходным экспериментом.
Метод/пороги в карточке не настраиваются.

## Обработка и зависимости

Обычный worker перед захватом следующего задания сверяет сохранённые состояния:
text → extract → prepare → link → done. На extract запускается только оперативная
модель. Координатор — короткая транзакция с advisory lock и блокировкой клиента;
во время inference эти блокировки не удерживаются. Jobs сохраняют SKIP LOCKED,
кэш и прежнее восстановление. Ограниченные CLI-выборки jobs не продвигают чужие
рабочие конвейеры.

Поиск ждёт подготовки карточек остальных документов клиента/версии, включая
другие пакеты. Успешно определённые входящие не входят в пул договоров. Неизвестные
вид/дата потенциального договора, отсутствие/ошибка извлечения не исключаются
молча: сохраняется error с объяснением и снимком зависимостей. Будущий договор
исключается только при успешном извлечении и известных реквизитах.
Независимые клиенты продолжают обработку.

При готовых карточках подготавливаются необходимые векторы входящего и допустимых
договоров, затем сохраняются исход и полный рейтинг. Договор без входящих не требует
предварительного вектора. Реальные BGE-M3/pgvector и ключи кэша прежние, fallback нет.
Ошибки embed явно отражаются в исходе. Изменение карточки/извлечения/пула/вектора
меняет вход поиска. После успешного повтора координатор возобновляет зависимости;
старые результаты и окончательные связи сохраняются. Проверка актуальности перед
подтверждением учитывает неполный пул.

При успешном извлечении с неизвестными видом или датой самого источника — review
(`unknown_source_kind_or_date`), даже при проблемах потенциального договора.
Правка карточки запускает подготовку/поиск без повторного извлечения.
Сбой text/extract сохраняет отдельный error, видимый в очереди проверки.

## Повторы

Доступны повтор неудачного этапа, повтор поиска и явное повторное оперативное
извлечение; сохраняется отдельное извлечение выбранной модели. При остановленном
text/extract продолжается прежнее задание, включая журнал попыток и начальный ответ
перед коррекцией. При ошибке embed повторяется ошибочный вектор документа,
зависимые поиски возобновляются после его готовности. Успешные этапы сохраняются.
Лимиты, защита неопределённой отправки и сохранённых ошибок YandexGPT остаются
общими. Автоматического перехода на другую модель нет. Переходы после остановки
worker восстанавливаются из БД, а не callback в памяти. Ошибка не успешный кэш.
