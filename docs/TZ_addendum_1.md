## 1. Назначение и состав

Основной корпус v2 содержит 233 документа (231 in_scope), 156 эталонных связей
от 138 входящих документов; входящих документов без эталонного договора нет.
Третья часть `corpus/synth_extra/` проверяет обоснованный отказ от рекомендации.

| case | Входящих | Ожидаемый исход |
|---|---:|---|
| no_target | 6 | разбор или нет кандидатов, без рекомендации |
| multi3 | 3 | ручной разбор: три договора |
| conflict | 4 | разбор с пояснением противоречия номера |
| same_number | 2 | альтернативы и разбор: один номер без даты, два договора |

Всего **19 текстов: 15 входящих документов и 4 договора-кандидата**, 15 эталонных
связей. Дополнительные колонки `case` и `expected` — только оценочная разметка.
Клиенты общие с synth, цели связей могут находиться в synth или synth_extra.
Объединённый корпус: 252 документа, 250 in_scope, 171 связь от 147 источников,
153 входящих документа (в том числе 6 без договора).

## 4. Приёмка контрольных случаев

Комбинированный метод с выбранной моделью не должен выдавать рекомендации ни по
одному из 15 входящих контрольных документов. Для multi3, conflict, same_number
ожидается разбор; для no_target — разбор или нет кандидатов.

Выгрузка «Контрольные случаи» содержит документ, case, expected, фактический исход
и пояснение. Часть tune/test показывается явно: проверка всего набора не объявляется
тестовой метрикой. Несоблюдение требования фиксируется в отчёте; пороги по test
не подгоняются. После просмотра test изменения метода оформляются новым протоколом
с reused_test. Расширение корпуса фиксируется в протоколе и не делает прежний test новым.

Отладочное утверждение из исходного дополнения (regex/TF-IDF: все 15 дали разбор)
и описание слабости rules — сведения автора комплекта, не результаты сервиса.
Сравнение rules, semantic, combined должно быть выполнено и показано в п. 2.3.

## 5. Fixtures сервиса

Небольшие примеры с известным ответом в tests/fixtures/ не входят в эксперимент.

| № | Проверка | Ожидается |
|---|---|---|
| F1 | договор позже акта | не кандидат |
| F2 | договор в день акта | кандидат |
| F3 | дата не извлечена | разбор, без подстановки |
| F4 | бухгалтер исправил вид | повторный поиск |
| F5 | ссылка 12-0К/25, договор 12-ОК/25 | num = 0,9 после OCR-нормализации |
| F6 | номер совпал как есть | num = 1,0 |
| F7 | ссылки А от 01.01 и Б от 01.02, договор А от 01.02 | date = 0, даты разных ссылок не смешиваются |
| F8 | явный номер не совпал | без рекомендации, пояснение расхождения |
| F9 | две однозначные отдельные ссылки | две рекомендации |
| F10 | одна ссылка без даты, два договора с этим номером | альтернативы, без рекомендации |
| F11 | три однозначные ссылки | ручной разбор |
| F12 | равные оценки лидеров | разбор |
| F13 | таймаут после ограниченных транспортных повторов | ошибка обработки, в N, пропуск Recall при gold, вне M |
| F14 | нет рекомендаций | Precision = 0, M = 0, доля ошибок «—» |
| F15 | 100 входов, 60 с рекомендациями, 70 связей, 63 верные | охват 0,60, Precision 0,90 |
| F16 | рекомендация не подтверждена | записи в links нет |
| F17 | на tune нет допустимого порога Precision ≥ 0,98 и M > 0 | NO_FEASIBLE_CONFIGURATION |

F13 использует действующую политику ограниченных повторов сервиса, без изменения
числа сетевых попыток этим дополнением.
