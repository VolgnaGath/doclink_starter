# Техническая приёмка связывания — этап 4.6

03.11.2026. Выбранная конфигурация первой приёмки: **combined + Qwen**, общая
регистрационная карточка Qwen, исходные веса/штрафы этапа 4, реальный BGE-M3.
Полная матрица трёх методов и трёх моделей, абляции, графики и `experiment_runs` — этап 6.

Приёмка не вызывает внешние модели и не повторяет извлечения. Используются результаты
4.5, включая две сохранённые ошибки YandexGPT. Новые расходы на LLM не требуются.

## До просмотра исходов test

1. `make embed` обрабатывает все 252 документа, независимо от split и разметки:

   ```sh
   make pause-worker
   make embed EMBED_RUN_FLAGS=-d ARGS='--corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f --drain'
   make accept-linking ARGS='embedding-audit --corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f --output docs/reports/embeddings.json'
   ```

   `embedding-status` вместо `embedding-audit` показывает продвижение очереди.
   Аудит требует точный актуальный ключ каждого вектора, не только наличие строки.
   Повтор `make embed` без retry не ставит завершённые задания заново; повтор с retry
   проверяет физический кэш без повторного кодирования.

2. Выбор порогов и freeze выполняются одной операцией `tune`. В оценочный знаменатель
   попадают **все in_scope входящие по разметке**, включая no_target и ошибки; ошибочный
   вид рабочей карточки не исключает документ. Вход метода строится отдельным адаптером
   без gold, split, case, expected, путей и чужих ответов. Цели-кандидаты — полный
   допустимый пул договоров той же версии независимо от split.

3. Процедура `stage4-tune-v1`, записанная до первой приёмки test:
   - используются только входящие `split=tune`; явный test-вход чистая функция отвергает;
   - конечные точки τ: 0, 1 и фактические оценки допустимых кандидатов в [0, 1];
   - τ_a: максимальный охват документов при Precision ≥ 0,98 и M > 0;
     при равном охвате — большая Precision, затем больший τ_a;
   - если допустимого τ_a нет — **NO_FEASIBLE_CONFIGURATION**, config=null,
     test не запускается; произвольный порог не подставляется;
   - при выбранном τ_a выбирается τ_r ≤ τ_a: максимум эталонных связей, доступных
     через рекомендации либо top-3 для разбора; затем минимум документов на разборе,
     затем больший τ_r. Это явная эвристика маршрутизации на tune, не доказательство
     оптимальности и не настройка на контрольном test;
   - веса, штрафы, проверки, модели и подготовка остаются исходными. Подгонка после test
     не выполняется. Кривые выбора и выбранные tune-метрики сохраняются в JSON.

4. Freeze содержит метод/пороги, embedder, снимки протоколов извлечения, fingerprint
   корпуса, SHA-256 фактического кода метода/адаптеров/оценки и хеши входов **до**
   запуска test. Разметка фиксируется отдельным оценочным хешем и не входит в движок.
   Протокол хранится в `corpus_versions.report.linking_acceptance_protocols`; его
   неизменяемый payload хешируется отдельно от признака `test_started` и времени фиксации.
   История просмотренного test v2 сохранена, первая приёмка связывания имеет
   `reused_test=true`. Новая версия корпуса не объявляется независимым test.

   ```sh
   make accept-linking ARGS='tune --corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f --model Qwen --method combined --output docs/reports/linking-freeze.json'
   ```

## Замороженная проверка и повтор

```sh
make accept-linking ARGS='run --corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f --protocol-hash HASH --output docs/reports/linking-live.json'
```

Перед jobs и перед оценкой сверяются код, корпус, выборка, карточки, независимые
извлечения, векторы и полный пул кандидатов. Изменение требует нового tune/freeze,
с сохранением `reused_test`; прежний протокол не переписывается. Test отмечается
начатым **до** обработки. `jobs link` сохраняют исходы и полные рейтинги с признаками,
штрафами, причинами и длительностями. Повтор переиспользует те же результаты, включая
сохранённые ошибки, и проверяет отсутствие новых физических LLM-вызовов/векторов.

JSON/Markdown показывают метрики tune и test отдельно. «Контрольные случаи» — 15
входящих synth_extra с явным split, case/expected, фактическим исходом, причинами,
кандидатами и ссылками на результат. Метки присоединяются **после** метода.
Для no_target проверяется разбор/нет кандидата без рекомендации; для остальных —
разбор с соответствующей причиной: три ссылки, противоречие, неоднозначность.
Отсутствие рекомендации без требуемого объяснения не выдаётся за полный успех.

Ошибка модели в контрольном случае остаётся измеренным нарушением требования:
код/пороги не правятся по test. Завершение реализации и статус контрольной приёмки
отражаются отдельно. После работ обычный worker возвращается через `make resume-worker`.
