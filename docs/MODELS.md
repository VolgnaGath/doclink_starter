# Модели и извлечение

## Подготовка

После обновления кода пересоберите образ, примените миграции и начальные данные
целями `make build`, `make migrate`, `make seed`; затем перезапустите сервисы.
Список команд и параметров — `make help`.

Seed идемпотентен: существующие конфигурации и промпты не меняет. По умолчанию активен
только локальный Regex. Облачные конфигурации имеют пустые тарифы, чтобы неизвестная
цена не превратилась в нулевой расход. На `/models` задаются URI, параметры генерации,
оба тарифа в рублях за 1000 токенов, активность и единственный источник карточки
по умолчанию. Снимки уже поставленных заданий и исторические результаты не меняются.

Ключи берутся из `.env`: `YC_API_KEY`, `YC_FOLDER_ID`, `GIGACHAT_AUTH_KEY` и
`GIGACHAT_SCOPE`. Поддерживаются также имена `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`,
`GIGACHAT_CREDENTIALS`. Для облачных вызовов необходимы `LLM_PROVIDER=live`,
`PAID_CALLS_ENABLED=true`, положительный `BUDGET_RUB` и заполненные тарифы.
По умолчанию `LLM_PROVIDER=mock`: сетевых вызовов и вымышленных ответов нет.
Для Ollama также нужен `LLM_PROVIDER=live`; платный допуск к нему не применяется.

Цепочку сертификатов GigaChat готовят по `certs/README.md`. TLS всегда проверяется.
`OLLAMA_URL` и `LLM_TIMEOUT_SECONDS` задают адрес локального сервера и таймаут.

`GIGACHAT_API_URL` по умолчанию — `https://api.giga.chat/v1` (актуальный адрес из кабинета).
`make check-gigachat` выполняет только OAuth и GET `/models`, `/balance`, даже при mock:
эта явная диагностическая операция не запускает генераций и не передаёт документы.
Ключи и access token не выводятся и не записываются в БД. Ответ balance 403 не доказывает
ошибку ключа: этот метод предназначен для пакетов и недоступен при pay-as-you-go.
Остаток не переводится в рубли и не подменяет проверку тарифов/денежного бюджета.

01.11.2026 сертификаты с Госуслуг установлены из пользовательских DER `.cer`
(root + sub + sub2024), проверка TLS и OAuth прошла. `/models` подтвердил `GigaChat-2`;
`/balance` вернул остаток категории GigaChat 250 млн токенов. Ответ не сообщает цену,
происхождение или срок пакета; наличие токенов не означает нулевую себестоимость.

`make configure-yandex ARGS='...'` явно обновляет URI и оба тарифа Qwen/YandexGPT,
не меняя активность, платный допуск и историю снимков. Параметры перечислены в `make help`.
Пользователь выбрал `qwen3.6-35b-a3b/latest` и `yandexgpt-5.1/latest`; на его скриншоте
тарифы составляют 0.20/0.30 и 0.80/0.80 ₽ за 1000 вход/выход с НДС. Согласованный лимит
500 ₽ на Yandex и отдельно 500 ₽ на GigaChat согласованы пользователем.

Лимиты `YANDEX_BUDGET_RUB` и `GIGACHAT_BUDGET_RUB` проверяются независимо под той же
блокировкой резервирования, что общий `BUDGET_RUB`. Если задан хотя бы один лимит
провайдера, для каждого вызываемого облачного провайдера необходим положительный лимит.
Локальная приёмка использует 1000 ₽ общего предела и 500 ₽ на каждого провайдера.

Проверена страница https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs
(01.11.2026): Freemium Lite 250 млн токенов, опубликованный платный пакет Lite — 20 млн
за 1300 ₽ с НДС. Для сравнения берётся 0.065 ₽/1000 входных и выходных токенов,
`cost_basis=reference_tariff_freemium`. `cost_rub` — тарифный эквивалент, а не доказательство
списания с карты; неизвестное фактическое списание сохраняется null в usage_details.
Кэшированные входные токены Yandex учитываются по их отдельному тарифу, если usage сообщает
их количество. Без такой детализации вход консервативно оценивается по полному тарифу.

`make configure-acceptance` задаёт эти настройки, активирует три облачные модели и выбирает
Qwen источником рабочей карточки. `reasoning_effort=none` у Qwen соответствует настройке
на его странице, исключает расход лимита ответа на рассуждения. Перед CLI-приёмкой
обычный worker останавливается через `make pause-worker`, после неё возвращается через
`make resume-worker`. `--workers 3` позволяет выполнять задания параллельно, при этом
генерации GigaChat сериализуются в PostgreSQL: у Freemium один поток.

Живая проверка 01.11.2026 потребовала включить GigaChat JSON-schema и обязательные поля
верхнего уровня, затем ввести инструкцию/схему **v2** через `make seed ARGS='--prompt-version v2'`.
v1 не перезаписывается. Отсутствующие реквизиты представлены null, нулевая дата запрещена.
`make smoke-paid ARGS='--mode smoke --model "GigaChat 2 Lite" --retry'` проверяет одну модель;
без --model smoke выбирает три облачные конфигурации.

Нативный `precached_prompt_tokens` GigaChat — бесплатный вход: его прибавляют к полному
input_tokens, но исключают из тарифной стоимости. API total_tokens соответствует
оплачиваемой/списываемой части. Подтверждено схемой API и точной сверкой /balance.
Отчёт живой проверки: `docs/reports/stage3-live-2026-11-01.md`.

## Обработка и результаты

Загрузка получает текст и ставит активные конфигурации в `jobs`. Повтор получения
текста и повтор извлечения из карточки выполняются в worker. Каждый результат
независим; в карточке можно выбрать источник рабочих реквизитов. Неизвестный вид,
дата или вид «другое» дают разбор. Отдельная ошибка другой модели не перезаписывает
выбранную карточку. История извлечений, цитаты, метод проверки и физический вызов
доступны в документе; журнал и известные/неизвестные расходы — на `/calls`.

`make extract ARGS='--document UUID --drain'` обрабатывает выбранный документ локально;
вместо документа можно выбрать `--corpus-version UUID`, `--split tune`, `--model Regex`.
Без `--model` выбираются активные модели. Повтор команды продолжает очередь, но
не перезапускает терминальные ошибки и готовые результаты. `--retry` — явная новая
попытка с сохранением истории; успешный кэш не вызывает сеть. `--report-only` печатает
состояние, не запускает обработку. CLI обрабатывает только выбранную часть очереди.

Для платных сценариев используется `make smoke-paid ARGS='--mode smoke'`.
Допуск и бюджет должны быть также экспортированы в окружение команды Make;
они явно передаются контейнеру. `--mode smoke` выбирает три облачные конфигурации
по имени и технический текст, `--mode tune --corpus-version UUID` — настроечную часть.

Перед test выполните `make freeze-extraction ARGS='--corpus-version UUID'` с тем же
набором `--model`, который будет обрабатываться. Хеш и снимки сохраняются в отчёте
версии корпуса, отдельно от входа движка. Полный корпус запускается через
`make smoke-paid ARGS='--mode corpus --corpus-version UUID --protocol-hash HASH'`.
После просмотра test другая конфигурация помечается `reused_test`. Эта фиксация
касается извлечения; полноценные `experiment_runs` и их FK вводятся на этапе 6.

Отчёт отдельно показывает все документы и `in_scope`, ожидаемые пары, успехи,
ошибки, переиспользование, состояния заданий и реальные расходы физических попыток.
Наличие результата Regex не является результатом вызова облачной модели.

## Бюджет и восстановление

`BUDGET_RUB` — общий верхний предел известных расходов и незавершённых резервов
в текущей БД, а не новый лимит на каждый запуск. Перед каждой отправкой PostgreSQL
сериализует резервирование. Консервативная оценка учитывает UTF-8-размер входа,
схему, накладные токены и `max_tokens`. Известная стоимость заменяет резерв.
Неизвестные токены/стоимость остаются `null`.

До трёх безопасных транспортных повторов на всё задание и один корректирующий
запрос при нарушении схемы. Каждый вызов журналируется до отправки. Таймаут чтения,
обрывы записи, 5xx и авария worker после начала запроса трактуются консервативно:
исход неопределённый, автоматической повторной оплаты нет. Ошибка соединения до
отправки, 429 и обновление OAuth допускают ограниченный повтор. Ошибки OAuth сами
по себе не являются генерацией. Проверка цитат не вызывает дополнительных запросов.

Worker восстанавливает задания до отправки; завершённый успешный ответ можно
переиспользовать. Неопределённый расход блокирует дальнейшие платные запросы.
После сверки с провайдером выполните
`make reconcile-call ARGS='--reconcile-call UUID --cost-rub N --note "основание сверки"'`.
Стоимость и пояснение сохранятся в журнале. Затем возможен явный `--retry`.
При неопределённом исходе резерв не является гарантией фактического счёта провайдера.

## Модули и изоляция

- `extraction_schema.py` — выходная схема, локальный baseline, обрезка и проверка цитат.
- `anonymization.py` — словарь клиента под блокировкой, документные обратные замены.
- `providers.py` — ровно один запрос генерации; OAuth и проверяемый TLS.
- `model_calls.py` — физические попытки, резерв, ограниченные повторы и успешный кэш.
- `extraction.py` — подготовка только текста/клиента, результат и явный источник карточки.
- `jobs.py` — короткий захват SKIP LOCKED, session advisory locks и восстановление.

Цитаты проверяются по сегментам отправленного текста: склейка через границу обрезки
не подтверждается. Кэш учитывает клиента, фактические сообщения, URI и параметры
модели, инструкцию, схему и версию подготовки. Изменение тарифа не инвалидирует
ответ; стоимость физического вызова остаётся по старому снимку.

Обезличивание применяется ко всему тексту и контексту клиента до обрезки; уже
обезличенные документы не меняются. Словарь и `anon_maps` хранятся только в БД,
не входят в отчёты. Regex-конвейер также проходит подготовку, но не создаёт `llm_calls`.
Gold, split, deal_id, hard_types, пути и ответы других моделей не входят в запрос.

## Сверка документации — 01.11.2026

Проверены официальные страницы GigaChat: [модели](https://developers.sber.ru/docs/ru/gigachat/models),
[Lite и ознакомительная цена](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-2-lite),
[OAuth](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token),
[структурированный вывод](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output),
[сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).
OAuth: Basic authorization key, RqUID, scope, срок 30 минут, expires_at в миллисекундах.
Для `json_mode=true` GigaChat получает `response_format.type=json_schema` и `schema`;
Yandex/Ollama — `json_object`. По умолчанию JSON-режим не запрашивается, схема
проверяется приложением. JSON-режим не отменяет семантическую валидацию дат/сумм.

На странице Lite указана ознакомительная цена 65 ₽ за миллион токенов. Она не
подставлена автоматически: фактический тариф аккаунта нужно сверить перед запуском.
Страницы Yandex и загрузка сертификата gu-st.ru оказались недоступны из среды
разработки. Начальные URI — конфигурационные заготовки, не подтверждение доступности
конкретной версии. Точный ID Lite и актуальные URI Qwen/YandexGPT 5.1, тарифы и
цепочка TLS требуют проверки в рабочем аккаунте перед живой приёмкой.
