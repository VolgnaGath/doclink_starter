# Перенос извлечений между версиями корпуса

03.11.2026 · пункт 4.5 плана этапа 4.

## Preflight без генераций

`app/services/extraction_transfer.py` сопоставляет документы по стабильному
`corpus_doc_id`, клиенту, SHA-256, фактическому тексту и режиму обезличивания.
Изменение старого документа блокирует перенос; новое содержимое не объявляется кэшем.
Промпт выбирается так же, как в очереди: последний `extract` с порядком по дате/версии.

Для каждой пары документ/модель заново строятся сообщения после обезличивания
и явной обрезки. `request_hash` включает клиента, фактические сообщения, провайдера,
URI модели, параметры, промпт/схему/версию и версию подготовки. Идентичности файла
недостаточно. Успешная коррекция находится по `root_input_hash` исходного запроса.

Preflight не создаёт jobs и не обращается к провайдерам. Он **сохраняет локальные
словари подготовки**, чтобы повтор и apply использовали те же замены. Тексты,
gold, пути, `anon_maps` и реальные обратные замены в отчёт не выгружаются.

Отчёт содержит действия по парам, снимки моделей, ключи, ссылки на исходные
извлечения/вызовы, историю test, учёт всего физического расхода и оценки новых пар.
Пример для согласованного расширения:

```sh
make transfer-extraction ARGS='preflight --source-version 1b53cd0c-6eea-4cc3-b5a6-9eebbb6209a4 --corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f --output docs/reports/preflight.json'
make freeze-extraction ARGS='--corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f'
make transfer-extraction ARGS='apply --input docs/reports/preflight.json --output docs/reports/transfer.json'
```

## Применение и происхождение

Миграция `0006` добавляет `extractions.source_extraction_id`, `input_hash` и
`preserved_error`. Apply работает без создания провайдера, в одной транзакции:
блокирует версию/целевые документы, проверяет состав всех пар, актуальные конфигурации,
соответствие документов, ключи, вызовы и отсутствие активной обработки.
Устаревший preflight откатывается целиком. Повтор не создаёт новые извлечения.

- Успех: JSON берётся из исходного физического `llm_calls`, проверяются схема/цитаты,
  выполняются обратные замены целевого документа. Новый результат ссылается на прежний
  вызов и извлечение; новая физическая стоимость не создаётся.
- Два прежних невалидных ответа YandexGPT: переносятся статус ошибки, исходный вызов,
  ссылка на извлечение и ключ. `preserved_error=true`, `valid=false`, `cache_hit=false`.
  Это **не отрицательный кэш модели**: защита относится к явно перенесённому результату
  приёмки. Даже `--retry` не ставит такую пару повторно; прямой вызов конвейера с тем же
  ключом завершается до создания провайдера. Успешный глобальный кэш не улучшает ошибку.
- `stage_timings.stage=extract_transfer` учитывает длительность переноса, включая
  сохранённые ошибки. Рабочая карточка выбирается из явно заданной модели Qwen.
- История v2 и журнал физических расходов не переписываются. В отчёте новой версии
  хранятся `extraction_source_versions` и идентификатор использованного preflight.

## Протокол и просмотренный test

Протокол извлечения идентифицируется **парой corpus_version + protocol_hash**.
Хеш по-прежнему описывает снимки моделей/подготовки: неизменный метод сохраняет тот же
хеш, новая версия содержит отдельную запись с fingerprint корпуса и происхождением.

`extraction_protocols.test_history` учитывает явных предков и версии с пересечением
стабильных идентификаторов/клиентов. Поэтому новая CorpusVersion сама по себе не
обнуляет просмотр test, даже до apply. И freeze CLI, и постановка одиночного документа
проверяют историю. Другая конфигурация после просмотра test получает `reused_test=true`.
При неизменном извлечении v2 → расширение `reused_test=false`, но предшествующий
просмотр явно записан и не объявляется новым независимым test.

`cards` сохраняет отдельный манифест входа связывания: карточки/происхождение, хеш,
BGE-M3, метод, веса и штрафы. Он помечен `pending_tune_not_frozen`: `tau_a/tau_r=null`
до выбора на tune в 4.6. История просмотренного test сохраняется; в манифесте нового
метода связывания `reused_test=true`. Порог не назначается ради завершения 4.5.

## Бюджет и продолжение

Облачная обработка запускается только через `make smoke-paid` с `--preflight`.
Перед jobs повторяются сверка ключей и бюджетов; offline apply должен быть завершён.
По новым парам рассчитывается средний исторический расход на корневой запрос,
**включая наблюдавшиеся коррекции**, и отдельно консервативные UTF-8-резервы.
Среднее — прогноз, не гарантированная стоимость; сумма всех резервов не равна расходу:
после каждого ответа резерв заменяется фактической ценой. На каждом запросе остаются
действующие конкурентно-безопасные лимиты провайдеров/общего бюджета и запрет неизвестного
расхода. Лимиты не повышаются автоматически.

```sh
PAID_CALLS_ENABLED=true BUDGET_RUB=1000 make smoke-paid ARGS='--mode corpus --corpus-version 196ecb8f-fe6e-41c6-8785-a4faf69a6b1f --protocol-hash 84dcde38e8fb0c0863b065fbc817d9f6ea5aa854d671b5b57e761c5bcc157807 --preflight docs/reports/preflight.json --workers 1'
```

Если пара остановилась **до отправки** из-за бюджета, после новой сверки допускается
явный `--resume-budget-errors`. Он возобновляет прежнее задание, а не повторяет все
ошибки. Уже сохранённый начальный невалидный ответ используется для оставшейся
единственной коррекции; начальная генерация не оплачивается повторно. Счётчик безопасных
транспортных повторов учитывает прежние попытки задания. Исчерпанная коррекция и
перенесённые ошибки не возобновляются этим флагом.
