## 4.1. Входы, методы и спецификация решений

### Общая карточка и независимые извлечения (Q1)

- Клиент, рабочие вид и дата источника/договоров — из общей карточки, источник Qwen.
  Снимок карточек и его происхождение фиксируются до сравнения методов.
- Номер, ссылки, контрагент, сумма и предмет для combined — из извлечения выбранной
  модели. Ошибку её извлечения не заменять ответом Qwen или другой модели.
- Это сравнение методов/моделей **при общей регистрационной карточке**, не трёх
  независимых сквозных конвейеров. Ошибки вида/даты Qwen могут влиять на все методы;
  вид и дата каждой модели отдельно оцениваются как поля извлечения.
- Во входе ядра, запросах и векторах нет gold, case, expected, deal_id, split,
  hard_types, путей, исходных названий папок и ответов других моделей.
  Оценочные срезы/ожидаемые исходы присоединяет отдельный модуль после решения.

### Общие ограничения и базовые методы (Q2)

- Кандидат — договор того же клиента, в той же версии корпуса, с известной рабочей
  датой не позже даты источника. Без допуска; registered_at только для аудита.
- Все части версии и оба split доступны как пул договоров. Gold не отбирает цели.
- Неизвестные вид/дата источника → разбор; техническая ошибка необходимого извлечения
  → ошибка обработки, без автоматического перехода на другой метод.
- Rules — простой baseline по точному номеру из regex; semantic — простой baseline
  по смысловой оценке. Специальные проверки ниже относятся к combined; слабости
  baselines измеряются, а не скрываются общими защитами combined.
- Такое разграничение согласовано в интервью; оно уточняет роль baselines и не
  отменяет общие ограничения ТЗ. Требование всех 15 контрольных исходов адресовано
  combined с выбранной моделью. Совпадение с reference не является критерием.

### Признаки и начальная конфигурация (Q5, Q7)

| Признак | Начальный вес |
|---|---:|
| num | 0,45 |
| date | 0,15 |
| inn | 0,15 |
| name | 0,05 |
| sem | 0,20 |

- Оценка: взвешенная сумма признаков минус явно сохранённые штрафы.
  Отсутствующий признак даёт 0; веса не перераспределяются.
- Номер: сырой 1,0, после OCR-нормализации 0,9, префикс 0,8, сходство 0,7 по Ф6.
  До замораживания описать и проверить точные операции нормализации, префикса,
  сходства и наименования; не заимствовать поведение reference без fixtures.
- Номер и дата оцениваются внутри одной ссылки. Даты разных ссылок не смешиваются.
  Для однозначного разрешения используется сырой/OCR-нормализованный номер и,
  если дата указана, её точное совпадение. Допуск ±10 дней не вводится.
- Два договора с одним номером без даты ссылки → альтернативы. Номер совпал,
  явно указанная дата не совпала → разбор с пояснением.
- Ссылки с одинаковым номером и разными датами не сливаются при удалении дублей.
- Начальные настраиваемые штрафы: 0,20 при сумме документа выше 125% суммы договора;
  0,05 за некорректный заполненный ИНН. Неизвестные сумма/ИНН не штрафуются.
  Проверить границу 125%, валидатор ИНН и сохранение каждой причины штрафа.
- Это исходные эвристики, не оптимальные параметры. Корректировки только на tune,
  со снимком конфигурации и учётом истории просмотренного test.

### Цитаты, ссылки и решение целого документа (Q4, Q6, Q9)

- Общий evidence_ok=false не запрещает все рекомендации автоматически.
  Проверяются основания, на которых действительно строится решение.
- Ссылка без подтверждённой цитаты сохраняется как неподтверждённая: не доказывает
  однозначную связь, но не исчезает из анализа числа ссылок и неоднозначности.
  Если решение зависит от неё → разбор. Нельзя превратить три ссылки в две,
  молча отбросив неподтверждённую.
- Отсутствующая/плохая цитата суммы или наименования сама по себе не блокирует
  подтверждённую ссылку; признаки и состояние оснований сохраняются раздельно.
- Одна ссылка и несколько подходящих договоров → альтернативы; явное противоречие
  → разбор с пояснением; равные лидеры → разбор.
- Две рекомендации возможны только для двух отдельных подтверждённых однозначных
  ссылок, когда обе связи проходят порог. Если одна не разрешена или не проходит
  порог — разбор всего документа, найденные связи показываются кандидатами.
- Три и более договора по ссылкам → ручной разбор независимо от оценок.
  Частичных рекомендаций для неразрешённого документа в v1 нет.
- Проверки выполняются на полном допустимом пуле. Ограничение отображения top-3
  применяется после анализа, чтобы не скрыть неоднозначность и третью цель.

### Пороги и последовательность исходов (Q8, Q14)

Для combined порядок следующий:

1. Техническая ошибка → ошибка обработки.
2. Неизвестные вид/дата или установленное противоречие/неоднозначность → разбор.
3. Пустой допустимый пул → нет кандидатов.
4. Нет блокировок и выполнено правило рекомендации при S ≥ τ_a → рекомендация.
5. Иначе лучший S ≥ τ_r → разбор с кандидатами.
6. Иначе → нет подходящего кандидата, причина «оценки ниже порога».

Пояснения различают пустой пул и низкие оценки; это варианты исхода «нет кандидата».
Противоречие не превращается в отсутствие кандидатов из-за низкой оценки.
Конфигурация валидирует τ_r ≤ τ_a; значения и обработка равенств сохраняются.
В fixtures пороги заданы явно. Для живой проверки этапа 4 выбрать пороги только
на tune, сохранить процедуру/результат выбора и заморозить конфигурацию до test.
Условие τ_a: максимум охвата при Precision ≥ 0,98 и M > 0; если допустимого порога
нет, не назначать его произвольно и не объявлять качество достигнутым.
Автоматизация подбора, кривые и полная проверка F17 — этап 6.

## 4.3. BGE-M3 и смысловой вход (Q10)

- BGE-M3 в worker, CPU, 1024, pgvector; зафиксировать ревизию модели.
  Добавить необходимые зависимости в pyproject.toml и lock-файл.
- Смысловой вход — очищенный текст документа, не предмет, пересказанный LLM.

- До freeze описать очистку, разбиение/ограничение длины и обработку превышения
  контекста. Обрезка явная; для LLM сохраняется действующий флаг llm_calls.truncated.
- Фиксировать нормализацию векторов и меру сходства. На текущем небольшом корпусе
  точное ранжирование допустимого пула; приблизительный поиск не скрывает кандидатов.
- Кэш модели в volume. Ключ вектора: фактический подготовленный текст, ревизия
  модели, версия подготовки и параметры кодирования. Повтор не пересчитывает вектор.
- Ошибки embed журналируются; TF-IDF — явно выбранная отладочная конфигурация,
  а не незаметный fallback и не замена реальной приёмки BGE-M3.
