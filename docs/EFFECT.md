# Методика расчёта эффекта — effect-v1

Основание: Ф9 ТЗ и `plans/08-effekt-i-sdacha.md`. Это сценарный перенос результатов
на месячный поток, не измеренный эффект внедрения и не исследование manual vs assisted.

## Единицы и база

Все длительности на входе калькулятора — секунды на **документ**, деньги — рубли.
Исходные допущения черновика §1.3 (`cd.docx`, 31.10.2026, таблица 1.3): 60 договоров,
40 допсоглашений, 700 счетов, 500 актов, 400 УПД в месяц; N=1640 входящих для связей.
Карточка — 180 с, точный поиск — 120 с, неполный — 600 с, доля неполных — 0,25.
T_ASIS=180+0,75×120+0,25×600=420 с; N×420/3600=191,333… ч/мес.
Противоречие «допущения / хронометраж» в черновике не разрешено: это **допущения**.
Запросы клиенту (5%) и ошибки (2%) не монетизируются без времени операций.

## Человеческая работа TO-BE

Вводятся общее время на документ (например, регистрация вне карточки) и четыре
**полных** времени проверки: recommendation, review, none, error. Каждое включает
проверку/исправление карточки, все подтверждения/ручной поиск, решение и завершение.
Общее время не должно включать операции, уже вошедшие в эти четыре длительности.
Две рекомендации учитываются одним полным временем документа. Подтверждение каждой
связи обязательно. Ожидание API не прибавляется к труду автоматически.

Доли — число test-документов каждого исхода / все test-входящие выбранного done-прогона;
включаются ошибки и no_target. Четыре доли дают 1; M связей не является знаменателем.
T_TOBE = common_seconds + Σ(p_outcome × full_review_seconds_outcome).
При p=0 длительность категории не требуется. Если p>0 и нет времени, итог — null.

### Протокол замеров effect-review-v1

До открытия карточек команда подготовки фиксирует run/protocol/dataset, упорядоченный
по исходу и ID список test-результатов (первые k каждого исхода), рабочий набор и копии.
Порядок не зависит от скорости/успеха проверки. Измеряет **человек**: открыть карточку,
проверить документ полностью, принять решения и завершить. Не делать перерывов во время
сессии. При ошибке/перерыве не удалять сессию; причина исключения остаётся в аудите.
Заранее выбранное правило: первая открытая сессия каждого source_result_id; если она
незавершена/изменена/повторно обработана — исключить документ, не заменять быстрым повтором.
Сессии вне зафиксированного набора и интерактивные приёмки не входят в расчёт.
Требуются initial_inputs=true, соответствующий исходный результат и связанное завершающее
review_action; edit/reopen исключают замер. Из context берётся снимок происхождения на
открытие, проверяются также действия до завершения и текущее происхождение копии.
Полное время — review_sessions.duration_ms; связанные review_actions показываются
отдельно с накопительным временем, **не суммируются**. Среднее используется в формуле,
медиана, n, ID сессий/действий, исключения и отсутствующие категории выводятся рядом.
Без протокола статистика доступна для аудита, но не становится измеренным временем.
Неизмеренную категорию можно заполнить только явным пользовательским допущением с источником.

## Расходы и их область

Адаптер читает замороженный dataset серии и выбранный run, а не пересчитывает качество.
Источники извлечений — ID из run.snapshot; физические попытки, включая коррекции,
дедуплицируются по llm_call.id. Общая карточка и выбранная модель входят вместе.
Входящие test и договоры-кандидаты разделяются по документам снимка; общий вызов,
встречающийся в обеих группах, распределяется договорам и не дублируется.
Прочие (например tune) вычисления показаны отдельно и не входят в удельный test-прогноз.
Стоимость исходных вычислений, нулевой новый расход read-only расчёта и прогноз
эксплуатации — разные показатели. Неизвестная стоимость — null (известный подытог виден).
Тарифный эквивалент не означает денежный платёж; cash_debit=null.

Облачный сценарий: по умолчанию переменная цена — test-входящие / N_test;
подготовка новых договоров — число договоров в месяц × цена подготовки одного договора
(исходные вызовы подготовки / число договоров снимка). Пользователь может явно заменить
обе цены прогнозом и указать источник. Дополнительные переменные расходы включают OCR,
эмбеддинги и прочие операции, если они оплачиваются. Инфраструктура вводится отдельно.
Серверный сценарий: обе эксплуатационные цены вводятся явно, стоимость облачных исходных
вычислений остаётся справочной. Нулевую цену нельзя выводить из кэшированного повтора.
60 договоров не входят в базу AS-IS. Их денежная подготовка входит в C_f;
неучтённый человеческий труд подготовки задаётся отдельной месячной суммой.

## Формулы и отсутствие результата

Δh = N×(T_ASIS−T_TOBE)/3600; труд AS-IS/TO-BE = часы × ставка.
c = (T_ASIS−T_TOBE)×ставка/3600 − переменная цена − дополнительные расходы на документ.
C_f = инфраструктура + прочие постоянные расходы + подготовка договоров.
Эффект = N×c−C_f. N* = C_f/c, только c>0. Окупаемость = внедрение/эффект,
только эффект>0. При нулевых постоянных расходах и c>0 N*=0.
Для N* удельные расходы, структура исходов и месячная подготовка договоров считаются
постоянными при изменении N. Отрицательные Δh/эффект сохраняются. Без ставки доступны
часы, денежные показатели null. Незаданные расходы не считаются нулевыми.

Qwen подписывается «открытые веса, облачное размещение». Локальное время — только оценка
Σ(input_tokens/v_prefill+output_tokens/v_decode) при положительных скоростях, отдельно
по модели и области; задержка облачного API не является замером GPU.

## Воспроизведение

JSON-снимок содержит версию формул, время, входы/источники, протокол замеров,
run/corpus/protocol/dataset, результаты/физические вызовы/сессии/действия, результат
и SHA-256 канонического содержимого без поля calculation_hash. Markdown и форма
используют этот же снимок. Replay проверяет хеш и пересчитывает чистую формулу без БД.
Новые данные создают новый снимок, не меняют dataset эксперимента. Снимки не содержат
текстов документов, сырых ответов моделей, ключей, путей хранения и anon_maps.

Ограничения качества остаются: сравнение на общей карточке Qwen, reused_test=true,
test Precision=0,92632; 98% не достигнуты. Человеческие решения метрики не меняют.
