# Интеграция mock1c

Ограниченная модель OData из §4.5 ТЗ, не полноценный сервер 1С. В TypeSpec
REST `/api/v1` этот внешний протокол не включается.

## Inbox

Рядом с файлом `invoice.txt` положите `invoice.txt.json`:

```json
{
  "id": "5ff36d21-f756-492e-931a-267406de7627",
  "client_id": "b847d526-d3f6-441d-8707-c440698cfe8a",
  "client_name": "Демонстрационный клиент",
  "filename": "invoice.txt",
  "registered_at": "2026-11-04T12:00:00Z",
  "is_anonymized": false
}
```

Файлы публикуются атомарно: сначала оригинал, затем JSON. UUID и байты после
публикации неизменны; новая редакция — новый UUID. SHA-256 вычисляет mock1c.
Клиент — организация-владелец, не извлечённый контрагент. `is_anonymized`
по умолчанию false. Рабочие реквизиты извлекаются обычным конвейером.

Каталог: `GET /odata/standard.odata/Catalog_Документы?$filter=Дата gt datetime'…'`.
`value` содержит метаданные выше, `sha256`, `Дата` (UTC). Порядок — время/UUID;
каталог возвращается целиком, без неявного ограничения размера или пагинации.
Файл: `GET /odata/standard.odata/Файл/{id}`. Пути и ссылки извне не принимаются.

Коннектор хранит каталог до продвижения отметки и опрашивает с перекрытием
границы. Уникальность `(source, external_id)` исключает дубли. На уже известных
ID сравниваются хеш и метаданные. Конфликт виден, локальный оригинал не меняется.
Ошибки скачивания повторяются ограниченно; после трёх попыток — ручной повтор.
Для обнаружения нарушений неизменности mock1c проверяет опубликованный каталог
целиком; для намеренно добавленных записей с прошлой датой есть полный опрос CLI.

## Обратная запись

`POST /odata/standard.odata/РегистрСведений_СвязиДокументов`:
`event_id`, `link_id`, `review_action_id`, `operation=create|remove`,
`source_id`, `target_id`, `link_type`, `occurred_at`.
Все ID — UUID, стороны — внешние ID документов одного клиента.

Повтор event_id с тем же payload возвращает прежний результат; с другим — 409.
SQLite-журнал в volume сохраняет события и актуальные связи атомарно.
`GET /journal` — диагностический журнал заглушки (только метаданные связей).
Отмена возможна после создания. События одного документа доставляются по порядку.

В DocLink событие создаётся в транзакции действия бухгалтера. Сеть вызывается
worker отдельно, без транзакции решения. HTTP-сбои повторяются до трёх раз с
задержкой, event_id сохраняется даже после неопределённого сетевого исхода.
Отсутствующая внешняя привязка стороны даёт blocked, не фиктивный успех.
Для upload-документов без внешних ID автоматическая регистрация в 1С не предусмотрена.
Рекомендации не отправляются. Gold/тексты/anon_maps/ключи не экспортируются.

`/integration` показывает опрос, входящие записи, доставки и попытки, позволяет
явно повторить ошибку. Настройки: MOCK1C_ENABLED (по умолчанию true),
MOCK1C_POLL_SECONDS, MOCK1C_TIMEOUT_SECONDS, MOCK1C_URL. Секретов протокол
заглушки не требует. Отключение коннектора не меняет существующие документы.
Команды — `make help`.

## Приёмка

`docker-compose.integration-acceptance.yml` поверх verify создаёт отдельные
БД/файлы/inbox/журнал и API на 127.0.0.1:18000, mock1c на :18001.
Веса BGE-M3 разделяются только для чтения. Подготовка требует пустую БД и явный
INTEGRATION_ACCEPTANCE_ENABLED, не читает основную `.env`.
Используется настоящий regex-извлекатель и настоящий BGE-M3 CPU. Это проверка
транспорта/конвейера/подтверждений, не измерение качества облачных LLM; пороги
технической пары не переносятся в замороженный эксперимент или рабочую конфигурацию.
Chromium проверяет подтверждение, остановку mock1c, отмену, доставку после
восстановления, повторный опрос и рестарт. Итог проверяется независимым DB-аудитом.
Снимки основного стенда до/после содержат только счётчики и хеши, без текстов/gold.
