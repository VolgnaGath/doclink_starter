# Чистое ядро связывания v1

02.11.2026. Реализация пунктов 4.1–4.2 плана этапа 4. Это спецификация
детерминированного алгоритма, не результат измерения качества моделей.

## Граница ядра

`app.services.linking.link(input, config)` не обращается к БД, файлам, моделям
или эталону. Входные Pydantic-объекты неизменяемые, неизвестные поля запрещены.
Адаптер передаёт только разрешённые поля, а не ORM-объекты или `documents.gold`.

- `Card`: идентификаторы документа, клиента, версии корпуса, рабочие вид/дата,
  техническая ошибка карточки. Карточка общая, источник Qwen; её происхождение
  и снимок должен сохранять будущий адаптер хранения.
- `Fields`: реквизиты выбранного извлечения, ссылки с проверкой цитаты,
  отдельные признаки проверки оснований, техническая ошибка. Пустое поле
  отличается от неуспешного извлечения: последнее передаётся через `error`.
- `Document.text`: текст для regex baseline. Пути/имена папок не передаются.
- `Similarity`: фактический cosine к каждому допустимому договору. Отсутствующая
  оценка — ошибка, а не ноль. Получение векторов и кэш — следующие пункты этапа.

Для пользовательских документов `corpus_version_id=null`; для корпуса совпадает
версия. Все методы исключают чужих клиентов/версии, самого источника, неизвестные
даты, цели не-договоры и будущие договоры. Источник без вида/даты идёт на разбор.
Входящий вид — допсоглашение, счёт, акт или УПД; договоры не обрабатываются как
входящие. `registered_at` в интерфейсе ядра отсутствует.

## Операции признаков

Версия операций — `linking-v1`, включена в конфигурацию результата.

1. **Номер:** буквальное равенство непустых строк → 1. Иначе удаление начального
   `№` (до NFKC, который разворачивает этот знак в `No`), NFKC, верхний
   регистр, Unicode-дефисы → `-`, удаление пробельных символов,
   затем OCR-замены `0/O→О`, `K→К`, `A→А`, `B→В`, `C→С`, `E→Е`, `H→Н`, `M→М`,
   `P→Р`, `T→Т`, `X→Х`. Равенство → 0,9. Цифра 0 сохраняется в сыром сравнении;
   OCR-равенство не объявляется буквальным.
2. **Префикс:** после нормализации короткая строка длиной ≥3 — начало длинной,
   следующий символ `/` или `-` → 0,8. `123` не является префиксом `1234`.
3. **Сходство:** обе нормализованные строки длиной ≥4, `SequenceMatcher`
   (`autojunk=False`) ≥0,85 → 0,7. Иначе 0. Для однозначного разрешения ссылки
   допускаются только значения 1/0,9; префикс/сходство — численные признаки.
4. **Дата:** 1 при точном совпадении явно указанной даты ссылки с рабочей датой
   цели; иначе 0. Из ссылок с ненулевым номером выбирается одна с максимальным
   `w_num*num + w_date*date`, при равенстве первая во входе. Номер и дата других
   ссылок в эту пару не подмешиваются.
5. **ИНН:** точное равенство двух непустых валидных ИНН → 1. Проверяются длина
   10/12, ASCII-цифры и контрольные суммы ФНС, одинаковые цифры отвергаются.
   Строки ИНН автоматически не исправляются и не очищаются от мусора.
6. **Наименование:** NFKC, нижний регистр, ё→е, выделение буквенно-цифровых
   токенов; удаляются отдельные ООО/АО/ПАО/ОАО/ЗАО/ИП. Далее отношение
   `SequenceMatcher(autojunk=False)`, без сортировки токенов. Пустое даёт 0.
7. **Смысл:** cosine нормализованных векторов ограничивается снизу нулём.
   Вход валидируется в диапазоне [-1,1]; NaN/Infinity запрещены.

Начальные веса 0,45/0,15/0,15/0,05/0,20, сумма обязана быть 1. Неизвестный
признак даёт 0, веса не перераспределяются. `no_sem` обнуляет только вклад sem.
Штраф 0,20 — строго при сумме источника >1,25 суммы цели, сравнение Decimal.
Штраф 0,05 — за каждый заполненный некорректный ИНН (источник и цель отдельно).
Неизвестные значения не штрафуются. Причины штрафов сохраняются; оценка может
быть отрицательной, её не ограничиваем нулём.

## Решение документа

Повторные упоминания нормализованного номера **и той же даты** объединяются;
достаточно одного подтверждённого упоминания. Разные даты не сливаются.
У каждого упоминания, включая неподтверждённое, проверяется полный допустимый
пул. Для разрешения: сырой/OCR-номер и точная дата при её наличии. Нет совпадения
номера/даты → явное противоречие; несколько целей → неоднозначность; нет номера
или подтверждённой цитаты → разбор. Неподтверждённый номер единственной найденной
цели также требует разбора: проверяются основания обеих сторон сопоставления.
Три ссылки или три цели → разбор.

Технические ошибки необходимых входов имеют приоритет. Затем неизвестная
карточка, противоречия/неоднозначности, затем пустой пул, затем пороги.
Две разные разрешённые цели рекомендуются только вместе, если обе ≥tau_a;
иначе разбор целиком. При одной разрешённой цели рекомендация возможна только
для неё. Без ссылок оценивается лидер общего рейтинга. Равные лидеры (абсолютная
разница ≤1e-12) → разбор; порядок отображения при равенстве — по target_id.
Оценка ≥tau_a даёт рекомендацию, иначе лучший ≥tau_r — разбор, иначе `none`.
Конфигурация требует 0≤tau_r≤tau_a≤1, пороги без значений по умолчанию.

Общий `evidence_ok` не используется как запрет. Подтверждение цитат ссылок
проверяется отдельно; отсутствующая цитата суммы/контрагента не отменяет
подтверждённую ссылку. Состояние оснований сохраняется рядом с признаками.
Весь рейтинг возвращается до top-3, чтобы отображение не скрыло альтернативы.
Тип связи: допсоглашение → изменение, счёт → основание, акт/УПД → исполнение.

**Baselines:** rules сопоставляет буквальные номера из regex-ссылок текста
источника с номером заголовка договора (`regex_extract`), оценка 0/1; semantic
использует только cosine. Они сохраняют общие ограничения и собственную обработку
равных лидеров, но не проверки явных противоречий, нескольких ссылок или штрафы.
Ошибка ненужного им LLM-извлечения не блокирует baseline. `combined checks=false`
отключает специальные блокировки, равные лидеры и штрафы; обязательные ограничения
и технические ошибки остаются. Это намеренно ослабленная абляция.

## Оценка отдельно от движка

`app.services.evaluation.evaluate` получает уже рассчитанный результат и эталон.
Выбор split/среза и только входящих документов — обязанность вызывающего оценщика.
Каждая строка — один входящий документ; no_target и ошибки входят в N.
Precision считается по связям, охват по документам, альтернативы не входят в M.
При M=0 Precision=0, доля ошибок `null` (в интерфейсе «—»). Ошибки с gold снижают
Recall и не могут быть полностью верно обработанными. Recall@3 — доля gold-связей
документов на разборе, найденных в первых трёх кандидатах. При пустом знаменателе
численные метрики равны 0. Порогов оценщик не подбирает.

Fixtures F1–F3/F5–F15 и положительные/граничные примеры не являются модельными
метриками. Живая приёмка, tune/freeze, BGE-M3, хранение и worker ещё впереди.
