# DocLink

Прототип установления связей между документами договорного процесса и стенд
воспроизводимого эксперимента. Python 3.12, FastAPI/Jinja2, PostgreSQL 16/pgvector,
BGE-M3 CPU, очередь в БД. Каждую окончательную связь подтверждает человек.

## Состояние и результаты

Этапы 0–7 завершены; калькулятор и материалы этапа 8 реализованы, состояние приёмки —
в [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) и [CONTEXT.md](CONTEXT.md).
Расширенный обезличенный корпус: **252 документа, 250 в оценке, 171 эталонная связь
от 153 входящих**. Базовая v2: 233/231 документа, 156 связей от 138 входящих.
Корпус — `corpus/real`, `synth`, `synth_extra`; история — `corpus_history/`.

На tune выбрана combined + Qwen; test Precision **0,92632**, целевые **0,98 не достигнуты**.
Сравнение условно на общей карточке Qwen, reused_test=true. Метод не улучшался по test.
Qwen: **открытые веса, облачное размещение**; локальное время только расчётное.
Матрица использует реальные извлечения и BGE-M3, включая две сохранённые ошибки YandexGPT.
Mock-провайдер предназначен для инфраструктурных тестов, не для отчётных метрик.

## Запуск с чистыми томами

Нужны Docker/Compose и Make. Для TypeSpec/браузерной приёмки — Node 22+;
требуется место под образы PyTorch и веса BGE-M3. Команды выполняются из корня.
Полный каталог команд — **`make help`**.

1. Создать `.env` по `.env.example`. Задать `APP_PASSWORD`, случайный `SECRET_KEY`,
   согласованные `POSTGRES_*`/`DATABASE_URL`. Пустые значения и `change-me` не принимаются.
   Оставить `PAID_CALLS_ENABLED=false`, `LLM_PROVIDER=mock`, `MOCK1C_ENABLED=false`.
2. `make build`, затем `make migrate` (БД запускается как зависимость, применяется 0011).
3. `make seed ARGS='--prompt-version v2'`, затем `make import-corpus`.
   Повтор импорта не создаёт версию заново; импорт выдаёт ID версии и состав.
4. `make embedding-download` загружает закреплённую ревизию BGE-M3 в том `models`.
   `make smoke-embedding` проверяет настоящий CPU inference, включая длинный текст.
5. `make up`. Войти на `http://localhost:8000/login` по `.env`.
   `/health` — публичная проверка, `/docs` — живой OpenAPI, mock1c — порт 8001.

Обычный чистый импорт **не содержит сохранённых облачных ответов и векторов**.
Для воспроизведения отчётной матрицы нужны переносимые реальные артефакты
([маршрут сдачи](docs/DELIVERY.md)) либо отдельно разрешённое извлечение.
Наличие seed не означает готовность облачных моделей или оперативного конвейера.
Без конфигурации `/documents/upload` объясняет отсутствие готового конвейера.

## Работа с моделями и документами

Провайдеры и лимиты: [docs/MODELS.md](docs/MODELS.md); Yandex API key/folder и GigaChat
client secret находятся только в `.env`. Сертификаты GigaChat устанавливаются
по [инструкции моделей](docs/MODELS.md), TLS не отключается. Бюджеты по умолчанию
не дают права новых платных вызовов. Новые облачные вызовы — только при явном
допуске, `PAID_CALLS_ENABLED=true` и положительном `BUDGET_RUB`, через платную make-цель.

После реальных извлечений и векторов: `/experiments` → матрица → tune/freeze/test →
CSV/Markdown/PNG. Команда `make experiments` исполняет ту же очередь, см.
[docs/EXPERIMENTS.md](docs/EXPERIMENTS.md). Для текущего корпуса оперативная
combined + Qwen ставится `make configure-pipeline` по сохранённой заморозке 4.6;
для другой версии нужна её собственная согласованная заморозка.

`/documents/upload` принимает пакет PDF/DOCX/TXT для рабочего клиента; неизвестная
обезличенность по умолчанию false. Карточки корпуса только для просмотра.
`/working-sets` и копии результатов эксперимента — отдельные рабочие документы без gold.
`/review` → все четыре исхода → проверка карточки/решения → завершение;
просмотр рекомендации сам по себе не создаёт связь. Подтверждения и отмены сохраняют аудит.

`/integration` — OData inbox/outbox и повторы. Чтобы включить опрос, задать
`MOCK1C_ENABLED=true` в `.env` и пересоздать worker (`make up`). Формат inbox и
условия отправки связей — [docs/INTEGRATION.md](docs/INTEGRATION.md).
`/effect` — сценарный расчёт часов/рублей, JSON/Markdown-снимки; отсутствующие
замеры и неизвестные расходы остаются неизвестными. Методика — [docs/EFFECT.md](docs/EFFECT.md).

## Проверка и воспроизведение

`make lint`, `make test` — без платных вызовов. `make verify-test` поднимает отдельную
PostgreSQL, выполняет интеграционные тесты; отдельный реальный BGE-smoke требует весов.
`make verify-down` очищает только проверочный стенд. `make down` останавливает основной
стенд и сохраняет его тома. Чистую сдачу с отдельными томами выполняйте по
[docs/DELIVERY.md](docs/DELIVERY.md), а не удалением рабочей БД.
